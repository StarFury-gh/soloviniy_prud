# Galery API

## Authentication

Для защиты ресурсов используется JWT-токен, который передается в заголовке `Authorization`:

```
Authorization: Bearer <your_jwt_token>
```

## Роли пользователей

| Роль | Описание |
|------|----------|
| `user` | Обычный пользователь (может загружать фотографии в галерею) |
| `admin` | Администратор (имеет доступ к управлению публикациями и статусами фотографий) |

---

## Endpoints

### 1. Get Photos (опубликованные)

**GET** `/galery/`

Краткое описание: Получение списка опубликованных фотографий с пагинацией.

#### Параметры

**Query параметры**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `limit` | integer | Нет | Количество записей на странице (по умолчанию: 5) |
| `offset` | integer | Нет | Смещение для пагинации (по умолчанию: 0) |

**Заголовки**:

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <token>` (опционально) |

#### Пример запроса

```
GET /galery/?limit=10&offset=0
```

#### Пример ответа (успех)

```json
{
  "publications": [
    {
      "publishing_id": "123e4567-e89b-12d3-a456-426614174000",
      "author": {
        "id": "123e4567-e89b-12d3-a456-426614174001",
        "name": "Ivan",
        "surname": "Ivanov"
      },
      "photos": ["abc123.jpg", "def456.jpg"]
    },
    {
      "publishing_id": "123e4567-e89b-12d3-a456-426614174001",
      "author": {
        "id": "123e4567-e89b-12d3-a456-426614174002",
        "name": "Petr",
        "surname": "Petrov"
      },
      "photos": ["ghi789.jpg"]
    }
  ]
}
```

#### Ошибки

| Код | Причина |
|-----|---------|
| `500 Internal Server Error` | Внутренняя ошибка сервера |

### 2. Add Photos

**POST** `/galery/add`

Краткое описание: Загрузка фотографий в галерею. Доступно всем авторизованным пользователям.

#### Параметры

**Заголовки**:

| Заголовок | Обязательный | Описание |
|-----------|--------------|----------|
| `Authorization` | Да | JWT-токен в формате `Bearer <token>` |

**Тело запроса (Body)**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `photos` | array of strings | Да | Список изображений в Base64 |

**Примечание**: 
- Обычные пользователи загружают фото со статусом `new` (ожидает одобрения)
- Администраторы загружают фото со статусом `approved` (немедленно публикуются)

#### Пример запроса

```json
{
  "photos": [
    "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQE...",
    "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
  ]
}
```

#### Пример ответа (успех)

```json
{
  "saved": ["xyz789.jpg", "abc456.jpg"],
  "status": true
}
```

#### Ошибки

| Код | Причина |
|-----|---------|
| `400 Bad Request` | Пустой список фотографий или неверный формат изображения (должен начинаться с `data:image`) |
| `404 Not Found` | Автор не найден (токен содержит несуществующий ID) |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

---

Краткое описание: Получение списка запросов на публикацию фотографий. Доступно только администраторам.

#### Параметры

**Query параметры**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `status` | string | Да | Статус публи��ации: `new`, `approved`, `rejected` |
| `limit` | integer | Нет | Количество записей на странице (по умолчанию: 5) |
| `offset` | integer | Нет | Смещение для пагинации (по умолчанию: 0) |

**Заголовки**:

| Заголовок | Обязательный | Описание |
|-----------|--------------|----------|
| `Authorization` | Да | JWT-токен в формате `Bearer <token>`, где токен принадлежит пользователю с ролью `admin` |


```json
      "publishing_id": "123e4567-e89b-12d3-a456-426614174001",
      "author": {
        "id": "123e4567-e89b-12d3-a456-426614174002",
        "name": "Petr",
        "surname": "Petrov"
      },
```

#### Ошибки

| Код | Причина |
|-----|---------|

| `404 Not Found` | Пользователь не найден (токен содержит несуществующий ID) |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

### 4. Update Publication Status (только администратор)

**PATCH** `/galery/status`

Краткое описание: Изменение статуса публикации (одобрить/отклонить). Доступно только администраторам.

#### Параметры

**Заголовки**:

| Заголовок | Обязательный | Описание |
|-----------|--------------|----------|
| `Authorization` | Да | JWT-токен в формате `Bearer <token>`, где токен принадлежит пользователю с ролью `admin` |

**Query параметры**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `publishing_id` | string (UUID) | Да | Идентификатор публикации |
| `new_status` | string | Да | Новый статус: `new`, `approved`, `rejected` |

#### Пример запроса

```
PATCH /galery/status?publishing_id=123e4567-e89b-12d3-a456-426614174000&new_status=approved
```

#### Пример ответа (успех)

```json
{
  "updated": true
}
```

#### Ошибки

| Код | Причина |
|-----|---------|
| `400 Bad Request` | Неверный формат токена или неверный статус |
| `404 Not Found` | Публикация не найдена |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

---

### 5. Delete Publication Photo (только администратор)

**DELETE** `/galery/photo`

Краткое описание: Удаление фотографии из публикации. Доступно только администраторам.

#### Параметры

**Заголовки**:

| Заголовок | Обязательный | Описание |
|-----------|--------------|----------|
| `Authorization` | Да | JWT-токен в формате `Bearer <token>`, где токен принадлежит пользователю с ролью `admin` |

**Query параметры**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `photo_path` | string | Да | Путь к удаляемой фотографии (имя файла) |

#### Пример запроса

```
DELETE /galery/photo?photo_path=abc123.jpg
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.admin_token
```

#### Пример ответа (успех)

```json
{
  "deleted_from": "123e4567-e89b-12d3-a456-426614174000",
  "deleted": "abc123.jpg"
}
```

**Примечание**: Если после удаления фотографии в публикации не осталось других фото, вся публикация удаляется из базы данных и файловой системы.

#### Ошибки

| Код | Причина |
|-----|---------|
| `400 Bad Request` | Неверный формат токена |
| `404 Not Found` | Фотография не найдена |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

## Описание полей ответов

### GaleryPhotoAuthor Object

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string (UUID) | Уникальный идентификатор автора |
| `name` | string | Имя автора |
| `surname` | string | Фамилия автора |

### GaleryPublication Object

| Поле | Тип | Описание |
|------|-----|----------|
| `publishing_id` | string (UUID) | Уникальный идентификатор публикации |
| `author` | GaleryPhotoAuthor | Информация об авторе |
| `photos` | array of strings | Список имен сохраненных изображений |

### GaleryPublicationStatus Enum

| Значение | Описание |
|----------|----------|
| `new` | Новая публикация, ожидает рассмотрения |
| `approved` | Публикация одобрена администратором |
| `rejected` | Публикация отклонена администратором |

---

## Статусы публикаций

Для управления публикациями используются следующие статусы:

| Значение | Описание |
|----------|----------|
| `new` | Новая публикация, ожидает одобрения администратора |
| `approved` | Публикация одобрена и отображается в общем списке |
| `rejected` | Публикация отклонена администратором |

---

## Пагинация

По умолчанию используется:
- `limit` = 5 (количество записей на странице)
- `offset` = 0 (смещение)

Пример:
```
GET /galery/?limit=10&offset=20
```

---

## Формат изображений

Изображения передаются в формате Base64 с префиксом MIME-типа:

```
data:image/jpeg;base64,/9j/4AAQSkZJRgABAQE...
data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...
```

Поддерживаемые форматы: JPEG, PNG (и другие, определяемые MIME-типом).

---

## Примечания

1. Публикации со статусом `approved` отображаются в общем списке через `/galery/`.
2. Публикации со статусом `new` и `rejected` доступны через `/galery/requests`.
3. Изображения сохраняются в директорию, указанную в `cfg_obj.UPLOAD_DIR`.
4. При создании публикации пользователи загружают фото со статусом `new`, а администраторы — со статусом `approved`.
5. При удалении последней фотографии из публикации, вся публикация удаляется автоматически.
6. Все ресурсы, кроме `/galery/`, требуют аутентификации.
